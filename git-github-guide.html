1. Git چیست؟

Git یک سیستم کنترل نسخه یا Version Control System است. یعنی تغییرات پروژه نرم‌افزاری را ثبت، مدیریت و قابل بازگشت می‌کند.

ساده‌ترین تعریف: Git حافظه هوشمند پروژه است.

Git چه کمکی می‌کند؟

  • تغییرات فایل‌ها را ثبت می‌کند.
  • می‌فهمی چه کسی، چه زمانی، چه چیزی را تغییر داده است.
  • اگر پروژه خراب شد، می‌توانی به نسخه قبلی برگردی.
  • می‌توانی برای قابلیت‌های جدید branch جدا بسازی.
  • کار تیمی را منظم و قابل کنترل می‌کند.

2. تفاوت Git، GitHub و GitLab

Git

ابزار اصلی کنترل نسخه است که روی سیستم خودت نصب می‌شود.

با Git می‌توانی commit بزنی، branch بسازی، تغییرات را ببینی و به نسخه‌های قبلی برگردی.

GitHub

یک سرویس اینترنتی برای نگهداری مخزن‌های Git است.

با GitHub می‌توانی پروژه را آنلاین کنی، با دوستان به اشتراک بگذاری و Pull Request بسازی.

GitLab

شبیه GitHub است و برای میزبانی repository، همکاری تیمی و CI/CD استفاده می‌شود.

خلاصه:
Git = ابزار مدیریت نسخه
GitHub/GitLab = سایت برای نگهداری و اشتراک‌گذاری پروژه Git

3. Git چه چیزی ذخیره می‌کند و کجا ذخیره می‌کند؟

Git چه چیزهایی ذخیره می‌کند؟

  • محتوای فایل‌ها
  • تاریخچه تغییرات
  • Commitها
  • Branchها
  • Tagها
  • اطلاعات نویسنده commit
  • زمان commit
  • ارتباط commitها با هم

Git کجا ذخیره می‌کند؟

وقتی داخل یک پروژه دستور git init را اجرا می‌کنی، Git یک پوشه مخفی به نام .git در ریشه پروژه می‌سازد.

ساخت repository محلی 
git init

ساختار ساده پروژه بعد از git init:

ساختار پروژه 
simple-project/
├── app.py
├── README.md
└── .git/

داخل پوشه .git چیست؟

بخش توضیح
objects داده‌های اصلی Git مثل فایل‌ها، commitها و treeها در این بخش ذخیره می‌شوند.
refs اشاره‌گرهای branchها و tagها را نگه می‌دارد.
HEAD نشان می‌دهد الان روی کدام branch یا commit هستی.
config تنظیمات محلی همین repository را نگه می‌دارد.
index اطلاعات Staging Area را نگه می‌دارد.

Git چطور ذخیره می‌کند؟

Git مثل این نیست که هر بار فقط یک فایل zip ساده از پروژه بگیرد. Git محتوای فایل‌ها و ساختار پروژه را به شکل object ذخیره می‌کند و برای هر object یک شناسه هش می‌سازد.

هر commit یک شناسه یکتا دارد، مثل:

نمونه شناسه commit 
e027f90 Update app.py with second message
8c51afd Initial commit
هر commit مثل یک عکس لحظه‌ای از وضعیت پروژه است؛ اما Git این کار را هوشمند و بهینه انجام می‌دهد.

چرا Git ذخیره می‌کند؟

  • برای اینکه تغییرات قابل ردیابی باشند.
  • برای اینکه بتوانی به نسخه‌های قبلی برگردی.
  • برای اینکه تیم بتواند با نظم روی پروژه کار کند.
  • برای اینکه بفهمی چه تغییری باعث باگ شده است.
  • برای اینکه نسخه‌های مختلف پروژه قابل مدیریت باشند.

4. چرخه کاری Git

Git معمولاً سه ناحیه اصلی دارد:

ناحیه توضیح
Working Directory همان فایل‌هایی که الان داری ویرایش می‌کنی.
Staging Area تغییراتی که آماده commit شدن هستند.
Repository تغییراتی که commit شده و در تاریخچه Git ثبت شده‌اند.
مسیر اصلی کار:
ویرایش فایل → git add → git commit → git push
چرخه رایج Git 
git status
git add .
git commit -m "Your commit message"
git push

7. اتصال پروژه به GitHub

قدم‌های کلی

  1. در GitHub یک Repository جدید بساز.
  2. اسمش را مثلاً simple-project بگذار.
  3. اگر قبلاً پروژه محلی داری، تیک ساخت README را نزن.
  4. دستورات remote و push را اجرا کن.

اتصال پروژه محلی به GitHub

افزودن remote 
git remote add origin https://github.com/USERNAME/simple-project.git

تغییر نام branch اصلی به main

branch اصلی 
git branch -M main

ارسال پروژه به GitHub

اولین push 
git push -u origin main
بار اول ممکن است GitHub از تو بخواهد در مرورگر login کنی و روی دکمه Authorize کلیک کنی. بعد از تأیید، به ترمینال برگرد و صبر کن تا push کامل شود.

push های بعدی

بعد از اولین push، معمولاً فقط کافی است بنویسی:

push بعدی 
git push

گرفتن آخرین تغییرات از GitHub

pull 
git pull

Clone کردن پروژه

دوستت برای دریافت پروژه می‌تواند این دستور را بزند:

clone 
git clone https://github.com/USERNAME/simple-project.git

8. Branch و Merge

Branch یعنی شاخه جداگانه برای کار کردن روی یک قابلیت یا اصلاح باگ، بدون اینکه branch اصلی پروژه خراب شود.

دیدن branchها

لیست branchها 
git branch

ساخت branch جدید و رفتن روی آن

ساخت branch 
git switch -c feature/add-homepage

رفتن به branch دیگر

تغییر branch 
git switch main

Merge کردن branch به main

اول روی main برو، بعد branch موردنظر را merge کن:

merge 
git switch main
git merge feature/add-homepage

ارسال branch به GitHub

push branch 
git push -u origin feature/add-homepage

حذف branch محلی

حذف branch محلی 
git branch -d feature/add-homepage

حذف branch از GitHub

حذف branch remote 
git push origin --delete feature/add-homepage

9. فایل .gitignore

فایل .gitignore مشخص می‌کند چه فایل‌ها و پوشه‌هایی نباید وارد Git شوند.

چرا لازم است؟

  • فایل‌های موقت وارد repository نشوند.
  • رمزها و اطلاعات حساس push نشوند.
  • حجم repository بی‌دلیل زیاد نشود.
  • فایل‌های مخصوص سیستم شخصی هر فرد وارد پروژه نشوند.
هرگز فایل‌هایی مثل .env، رمز دیتابیس، API Key و Token را داخل GitHub عمومی قرار نده.

نمونه .gitignore برای Python

نمونه .gitignore 
__pycache__/
*.pyc
.venv/
venv/
.env
*.log
.DS_Store
.idea/
.vscode/

ساخت فایل .gitignore

ساخت gitignore 
echo "__pycache__/" > .gitignore
echo ".env" >> .gitignore
echo ".venv/" >> .gitignore
git add .gitignore
git commit -m "Add gitignore"

10. اشتراک‌گذاری و کار تیمی

اشتراک با دوستان

اگر repository تو public باشد، لینک آن را برای دوستانت بفرست:

نمونه لینک repository 
https://github.com/USERNAME/simple-project

دوستت چطور پروژه را دریافت کند؟

clone توسط همکار 
git clone https://github.com/USERNAME/simple-project.git
cd simple-project

جریان ساده کار تیمی

  1. هر فرد آخرین تغییرات را می‌گیرد: git pull
  2. روی branch جدا کار می‌کند.
  3. تغییرات را commit می‌کند.
  4. branch را push می‌کند.
  5. در GitHub Pull Request می‌سازد.
  6. بعد از بررسی، تغییرات به main merge می‌شود.
جریان پیشنهادی کار تیمی 
git pull
git switch -c feature/my-task

# edit files

git status
git add .
git commit -m "Add my task"
git push -u origin feature/my-task

اشتراک با ChatGPT

برای کمک گرفتن از ChatGPT می‌توانی یکی از این‌ها را ارسال کنی:

  • لینک GitHub پروژه
  • خروجی git status
  • خروجی git log --oneline
  • ساختار پوشه‌ها
  • محتوای فایل‌های مهم
  • متن خطا
اطلاعات مفید برای ارسال به ChatGPT 
git status
git log --oneline --graph --decorate --all
git remote -v

11. خطاها و مشکلات رایج

خطای نام و ایمیل تنظیم نشده

اگر هنگام commit گفت user.name یا user.email تنظیم نیست:

حل خطای نام و ایمیل 
git config --global user.name "Your Name"
git config --global user.email "your@email.com"

خطای remote origin already exists

یعنی قبلاً remote با نام origin ساخته شده است.

دیدن remote موجود 
git remote -v

اگر آدرس اشتباه است، آن را تغییر بده:

تغییر آدرس origin 
git remote set-url origin https://github.com/USERNAME/simple-project.git

خطای authentication در GitHub

هنگام push ممکن است GitHub مرورگر را باز کند و از تو بخواهد login و authorize کنی. بعد از تأیید، به ترمینال برگرد.

اجرای مجدد push بعد از login 
git push -u origin main

اگر push گفت remote شامل تغییراتی است که تو نداری

اول تغییرات GitHub را بگیر:

pull قبل از push 
git pull --rebase origin main
git push

اگر اشتباهی commit کردی

اگر فقط پیام commit اشتباه است و هنوز push نکردی:

تغییر پیام آخرین commit 
git commit --amend -m "New commit message"

برگرداندن یک commit با commit جدید

روش امن برای undo کردن commit، مخصوصاً اگر push شده باشد:

revert 
git revert COMMIT_HASH

14. بهترین عادت‌ها در Git

  • Commitهای کوچک و معنی‌دار بزن.
  • پیام commit واضح بنویس.
  • قبل از شروع کار جدید، git pull بزن.
  • برای قابلیت‌های جدید branch جدا بساز.
  • فایل‌های حساس مثل .env را commit نکن.
  • قبل از push، git status را چک کن.
  • اگر مطمئن نیستی، قبل از اجرای دستورات خطرناک از یک نفر کمک بگیر.

نمونه پیام‌های خوب commit

commit message examples

git commit -m "Fix user validation bug"
git commit -m "Update README with setup instructions"
git commit -m "Add .gitignore for Python project"
git commit -m "Refactor payment calculation logic"
